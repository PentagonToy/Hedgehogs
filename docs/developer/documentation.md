# Documentation site

The independent [Hedgehogs site](https://pentagontoy.github.io/Hedgehogs/) publishes this repository's guides and API references through GitHub Pages. Nordic documentation remains separate.

## Source ownership

Edit `docs/`. The source preparation step maps `home.md` to the homepage and the documentation index to `overview.md`. It serves SVGs with content-hash revisions and points source links to GitHub. The [Sources page](https://pentagontoy.github.io/Hedgehogs/versions/) records the build commit when Git metadata is available; archive builds explicitly report its absence.

`others/assets/icon.svg` is the canonical transparent symbol used by the header and favicon. The README and homepage use `banner_light.svg` and `banner_dark.svg` from the same directory, selecting one for the active theme. Check both themes after artwork changes. Header, favicon and site artwork URLs are versioned automatically by content hash. The site's warm colours are independent of scientific plot palettes.

## Build and publish

Use a documentation environment containing `requirements-docs.txt`:

```console
python tools/docs/build.py --workspace /path/to/build/work --site-dir /path/to/output/site
```

Zensical renders the prepared sources; MkDocs core supplies the file adapter. The build replaces only output directories marked as generated by this tool.

The Documentation workflow builds and deploys relevant pushes to `main`. Builds render Markdown and serve committed gallery SVGs; they do not execute notebooks or scientific examples.

## Gallery updates

`tools/docs/gallery.py` renders synthetic examples into `docs/assets/gallery/`. After a relevant presentation change, run it explicitly, inspect the SVGs and commit them with the source. Site builds and ordinary tests do not regenerate the gallery.

Check generated links, artwork, installation tabs and light/dark presentation before publishing. Existing API pages remain the canonical references; keep introductory guides short.

## Notebook examples

The site imports selected notebook code and saved outputs without execution. Edit the notebook to update its page. Saved outputs are historical previews, not new validation results.

## Portable Markdown

Repository pages use standard Markdown and HTML details. Installation option groups use hidden `tabs` comments; source preparation converts them to MkDocs tabs. Check both ordinary Markdown and the built site after editing shared pages.
